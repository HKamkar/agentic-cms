# The command line

`agentic-cms <command>` runs against the site in the current directory: its
registry and config through `src/kit.ts`, its `content/`, `public/`, `.next`
and `.parity`. In this checkout it is `pnpm kit <command>`; on a site that
installs the package, `package.json` names the ones a build needs
(`content:lint`, `content:check`, `content:status`, `content:docs`, and
`build` runs `lint`, `docs --check`, `next build` and `seo` in that order).

The conventions every command keeps, because the caller is usually an agent:

- **Flags are strict.** An unknown flag is an error that names the fix (`run
  agentic-cms <command> --help`), never a silently ignored typo. `--help`
  anywhere prints the command's flags, defaults and exit codes.
- **Exit codes** mean the same everywhere: `0` clean; `1` findings or
  differences (the command did its job and found something); `2` usage or
  environment (a missing build, no browser, a bad flag).
- **`--json`**, where a command offers it, prints one JSON document on stdout
  and sends its progress to stderr, so the output parses without scraping.
- **Errors name the fix.** A missing build says `pnpm build`; a missing
  browser says what to install; a missing marker says which file. A wrong
  command, subcommand or flag names the nearest one ("did you mean"); a
  value outside a flag's choices lists them; a stray value after a
  repeatable flag says how to repeat it; a command that reads the site's
  registry (`lint`, `check`, `status`, `docs`, `seo`, `guard-email`)
  refuses to run outside a site's root (no `src/kit.ts`) and says so.
- **Every command has examples** in its `--help` and below — the form an
  agent copies. A numeric flag whose default is `0` means "not set, the
  command decides" (`--frames`, `--duration`, `--width`, `--resize`,
  `--max-width`, `--timeline`).
- **The families** are the map `agentic-cms --help` prints, in the order
  of the kit's layers ([parts.md](parts.md)): the content engine's
  commands; the design tools (the images, the proofs, the looks, the icons,
  the lab, the demo round); the site's commands (its setup, the gates its
  lint and build run by default, the steps a site adds to its build).

The table below is generated from the specs the parser reads
(`scripts/lib/specs.mjs`; `node tools/commands-doc.mjs`), so it is the
contract. The longer guides: [visual-parity.md](visual-parity.md) for the
screenshot harness, [shot-probe-sheet.md](shot-probe-sheet.md) for the
one-shot page commands, [init.md](init.md) for starting a site, [email.md](email.md) for the
e-mail guard, [deploy.md](deploy.md) for packaging a standalone build,
[icons.md](icons.md) for the icon commands, [lab.md](lab.md) for the design
canvas.

## content

Layer: [the content engine](parts.md#the-content-engine). `lint` · `check` · `status` · `docs` — `lint`, `check`, `status`, `docs` read the site's registry and run in its root

### `lint`

The content rules: every collection read as the build reads it, then the voice, SEO, body, image and date rules.

```bash
agentic-cms lint [--root <dir>] [--strict] [--production] [--report] [--json]
```

| flag | what |
|---|---|
| `--root <dir>` | another site tree (its content/ and public/) instead of the current directory |
| `--strict` | every WARN counts as a FAIL |
| `--production` | a production build: the starter's placeholder copy (a string carrying "(placeholder)") and a placeholder address (a URL, an e-mail or a domain reserved for examples: .example, .test, .invalid, localhost, example.com) FAIL instead of warning — a site's pnpm build passes it; AGENTIC_CMS_PLACEHOLDERS=warn in the environment keeps them warnings for that run, which a CI build that deploys nothing sets (the site's verify.yml) and a deploy never does |
| `--report` | also write the findings to .parity/content-lint-report.txt |
| `--json` | print the findings as one JSON document (the progress goes to stderr) |

Exit: `0` no FAIL; `1` a FAIL (a WARN is read, not failed, unless --strict): in a site, the kit example's brand at any time (Acme, acme.example, its author acme-editorial), and with --production a placeholder; `2` not a site (no src/kit.ts here).

`--json` prints `{ root, collections: [{ name, entries, source }], findings: [{ level, file, rule, path, problem }], summary: { fails, warns, strict, production, placeholders } }`.

```bash
agentic-cms lint
agentic-cms lint --production              # a site's pnpm build: placeholders fail
agentic-cms lint --strict --report        # every WARN counts; the findings also in .parity/content-lint-report.txt
agentic-cms lint --json | jq '.findings[] | select(.level == "FAIL")'
```

### `check`

The schemas alone: every collection read, one row each, in a fraction of a second.

```bash
agentic-cms check [--root <dir>]
```

| flag | what |
|---|---|
| `--root <dir>` | another site tree (its content/ and public/) instead of the current directory |

Exit: `0` every collection reads; `1` a ContentError (its lines printed, one per issue).

```bash
agentic-cms check
agentic-cms check --root ../other-site
```

### `status`

What is live, in draft and planned, read from the files: posts, pages, FAQ sets, reviews, use cases, the calendar, the backlog, recent changes.

```bash
agentic-cms status [--since 30.days]
```

| flag | what |
|---|---|
| `--since <git window>` | how far back the recent-changes list looks (default `30.days`) |

Exit: `0` printed.

```bash
agentic-cms status
agentic-cms status --since 7.days
```

### `docs`

The field tables of every collection, from the schemas, into content/README.md between its markers.

```bash
agentic-cms docs [--check]
```

| flag | what |
|---|---|
| `--check` | exit 1 when the tables are out of date instead of writing them (pnpm build runs this) |

Exit: `0` written, or up to date; `1` out of date (--check); `2` content/README.md has no markers.

```bash
agentic-cms docs                          # writes the field tables into content/README.md
agentic-cms docs --check                  # exit 1 when they are stale (pnpm build runs this)
```

## images

Layer: [design tools](parts.md#design-tools). `placeholder` · `optimize-webp` · `optimize-svg-rasters`

### `placeholder`

One wireframe placeholder image: a grey field, a hairline border, a corner-to-corner cross; the format follows the extension (.svg, .webp, .jpg, .png).

```bash
agentic-cms placeholder <out> <width> <height>
```

- `<out>` — the file to write
- `<width>` — pixels
- `<height>` — pixels

Exit: `0` written; `2` usage, or an extension that is not .svg/.webp/.jpg/.jpeg/.png.

```bash
agentic-cms placeholder public/images/home/hero.webp 1600 900
agentic-cms placeholder public/images/sections-about-og.jpg 1200 630
```

### `optimize-webp`

Re-encodes WebP files as lossy WebP in place when that saves enough (design exports are usually lossless).

```bash
agentic-cms optimize-webp [--quality 80] [--max-width <n>] [--min-saving 30] [--dry-run] <files-or-dirs...>
```

- `<files...>` — files, or directories walked for .webp

| flag | what |
|---|---|
| `--quality <n>` | WebP quality (default `80`) |
| `--max-width <n>` | also downscale pictures wider than this (0: never) (default `0`) |
| `--min-saving <n>` | rewrite only when the saving is at least this percent (default `30`) |
| `--dry-run` | print what would change; write nothing |

Exit: `0` done (a file that would not save enough is kept and says so); `2` a file or folder that does not exist, or usage.

```bash
agentic-cms optimize-webp public/images/blog/my-post
agentic-cms optimize-webp --dry-run --max-width 1600 public/images
```

### `optimize-svg-rasters`

Re-encodes the PNGs that design-tool SVG exports embed as base64 into WebP, in place; the drawing is untouched.

```bash
agentic-cms optimize-svg-rasters [--lossy] [--dry-run] [files...]
```

- `<files...>` — SVG files; without any, every SVG under public/images

| flag | what |
|---|---|
| `--lossy` | allow quality-80 WebP where it is smaller (for bitmaps used as alpha masks only) |
| `--dry-run` | print what would change; write nothing |

Exit: `0` done; `2` a file that does not exist, or usage.

```bash
agentic-cms optimize-svg-rasters              # every SVG under public/images
agentic-cms optimize-svg-rasters --lossy public/images/home/diagram.svg
```

## proof

Layer: [design tools](parts.md#design-tools). `parity` · `visual-parity`

### `parity`

Builds, then stores every prerendered page (scripts and hashed links stripped), its JSON-LD and the non-HTML routes under .parity/<label>/ for a diff -r.

```bash
agentic-cms parity <label>
```

- `<label>` — the capture's name under .parity/

Exit: `0` stored; `2` the build failed (see .parity/<label>.build.log), or usage.

```bash
agentic-cms parity before && … refactor … && agentic-cms parity after && diff -r .parity/before .parity/after
```

### `visual-parity`

The screenshot harness: every page of the build at several widths, frozen or in motion, and a pixel diff of two captures.

```bash
agentic-cms visual-parity <capture | compare | proof | clean> …
```

#### `visual-parity capture`

Screenshots of the build (or of a served site) into .parity/visual/<label>/; the site's own build is copied first, so the tree is free once the snapshot line is printed.

```bash
agentic-cms visual-parity capture <label> [--motion | --states] [--scheme light|dark] [--url <base>] [--widths w,w] [--pages /a,/b | --sample <n>] [--jobs <n>] [--fresh | --no-cache] [--storage <key>=<value>]… [--session-storage <key>=<value>]… [--no-storage]
```

- `<label>` — the capture's name under .parity/visual/

| flag | what |
|---|---|
| `--motion` | play the animations: viewport frames 150, 500 and 2000 ms after each scroll step, plus an inventory of every animation |
| `--states` | hover, focus, checked and open states, located by role and text; a state whose target the page lacks is skipped and listed in capture.json |
| `--scheme light|dark` | prefers-color-scheme for the capture; default the first of the profile's schemes (src/config/harness.ts), else light (one of `light`, `dark`) |
| `--url <base>` | capture a served site instead of serving .next (print its git log -1 first) |
| `--build` | run the site's `pnpm build` first (log: .parity/<label>.build.log) |
| `--ref <git ref>` | capture a baseline: that commit checked out in a sibling directory (../<site>-ref-<sha>), its demo routes removed, the tree's .env.local copied in, installed, built (reused for the same sha and .env.local once a build finished), served and captured |
| `--widths w,w` | viewport widths; default the profile's widths (src/config/harness.ts), else 1920,1440,1280,1100,992,800,767,390; --motion takes 1440,390 and --states 1440 without it; the home page's menu is opened at each of the profile's widths where its button shows (767 and 390 without a profile) |
| `--pages /a,/b` | only these routes (a partial capture; pass the same to compare); a demo route (/<name>-demo) is captured only when named here |
| `--settle <n>` | with --motion: the ms after a scroll step at which the settled frame is taken; an element's data-settle="<ms>" raises it while that element is in view (default `2000`) |
| `--sample <n>` | a static capture of the first n pages of each template (a dynamic route such as /blog-post/[slug], as the build's prerender manifest names it; never a catch-all), in route order; the rest are listed in meta.json and left out of a compare |
| `--third-party hold|allow` | other origins' scripts and connections (analytics, beacons, widgets) on a build the harness serves: held back by the page's Content-Security-Policy, or allowed; their images, fonts and stylesheets load either way; a --url site is captured as it serves itself (one of `hold`, `allow`) (default `hold`) |
| `--storage <key>=<value>` | a localStorage key on the page's origin, written before any of the page's scripts runs, over the site's src/config/harness.ts key by key; {now} in the value is the run's ISO time, {now:ms} its epoch milliseconds (repeatable) |
| `--session-storage <key>=<value>` | the same for sessionStorage (repeatable) |
| `--no-storage` | leave out the site's seed (the storage areas of src/config/harness.ts; its profile still applies): only the --storage and --session-storage given are seeded (a first visit) |
| `--jobs <n>` | browsers at work at once, each on its own page-widths (or states): default the cores less one, at most 4, for a static or --states capture, and 2 for --motion, whose frames are timed |
| `--fresh` | take every shot again: reuse none from .parity/shot-cache, where a page-width whose build files are all unchanged is otherwise copied (the cache is refreshed all the same) |
| `--no-cache` | take every shot and store none in .parity/shot-cache: a retake of shots in doubt (proof takes one of each shot that differs), which compare --retake-before / --retake-after accepts |
| `--json` | print the capture's summary as JSON (also written last as capture.json — its presence means the capture finished) |

Exit: `0` captured (a static shot taken with an image still loading after a reload is recorded beside it as <page>@<width>.unloaded.json, and a compare calls it FLAKY); `1` a page failed twice (no shot is taken of a stalled page), or the build failed; `2` usage, no build, no browser (playwright-core and a Chromium), or a seed that does not read (the flag or src/config/harness.ts is named).

`--json` prints `{ label, dir, pages, widths, files, seconds, jobs, reused: { shots, of } | null, timings: { taken, seconds, mean, slowest: [{ name, seconds }] }, skipped: [{ state, page, file, reason }] (--states), meta: { scheme, motion, states, settle, ref, sha, tree: { head, dirty } | null, build, fresh, sample: { n, skipped }, seed: { storage, sessionStorage, at } } }`.

```bash
agentic-cms visual-parity capture before --ref develop
agentic-cms visual-parity capture after --scheme dark --pages /,/blog
agentic-cms visual-parity capture after --motion --json
agentic-cms visual-parity capture after --storage 'consent={"analytics":"denied","at":"{now}"}'
```

#### `visual-parity compare`

Diffs two captures pixel by pixel; diff images under .parity/visual/<before>-vs-<after>/.

```bash
agentic-cms visual-parity compare <before> <after> [--threshold 0.02] [--threshold-mid 20] [--pages /a,/b] [--mixed-seed] [--retake-before <label>] [--retake-after <label>]
```

- `<before>` — the baseline's label
- `<after>` — the label to judge

| flag | what |
|---|---|
| `--threshold <n>` | percent of pixels a static or settled frame may differ by (default `0.02`) |
| `--threshold-mid <n>` | the same for the mid-flight motion frames (150 and 500 ms) (default `20`) |
| `--pages /a,/b` | judge only these routes' files, on both sides, at the widths the after capture took (a partial capture) |
| `--mixed-seed` | compare two captures seeded differently — what a seed itself changes; without it they are refused, like two schemes |
| `--retake-before <label>` | a capture --no-cache of the before side's build (the same build id, scheme, mode and seed), whose shots are fresh retakes of the before shots that differ |
| `--retake-after <label>` | the same for the after side: a shot of which some take of the after build matches some take of the before build does not reproduce, and is FLAKY; one whose every changed pixel lies where it also differs between two takes of one build is UNSTABLE |
| `--json` | print the report as JSON (also written as report.json in the diff directory) |

Exit: `0` identical within the thresholds; `1` a difference, a size change, a missing file, a flaky shot (one taken with an image still loading, or a difference a retake did not reproduce) or an unstable one (it differs only where it also moves between two takes of one build); each line that is not ok has its cause: line under it; `2` usage, a missing capture, captures of two schemes, captures seeded differently (without --mixed-seed), or a retake that is not a fresh take of its side's build.

`--json` prints `{ before, after, scheme, threshold, thresholdMid, pages, baseline, seed: { before, after }, geometry: { before, after }, retakes: { before, after } | null, unretaken: [name], summary: { ok, changed, size, missing, flaky, unstable, exit }, files: [{ name, kind, status, line, … changedPct, bands | verdict, head, tail, delta, band, crops | onlyBefore, onlyAfter | in, cause (every status but ok): { section, id, moved, top, height, delta, fractional, retake?, outside? } | { kind: unloaded | jitter | unstable | in-place | geometry | frame | missing | inventory | settle, …, retake?, outside? } }] }`.

```bash
agentic-cms visual-parity compare before after --json
agentic-cms visual-parity compare before after --pages /,/blog
agentic-cms visual-parity compare unseeded seeded --mixed-seed   # what the seed changes
agentic-cms visual-parity compare before after --retake-before before-retake --retake-after after-retake
```

#### `visual-parity proof`

A whole proof in one command: for the static pass, and for --motion and --states when asked, the baseline of a commit (--ref), the tree as it stands and the compare, each static shot and --motion frame that differs retaken once on both sides, fresh, before the pass reports; one summary, exit 1 on any line that is not ok.

```bash
agentic-cms visual-parity proof [label] [--ref <git ref>] [--motion] [--states] [--all] [--build] [--scheme light|dark] [--widths w,w] [--pages /a,/b | --sample <n> | --all-pages] [--jobs <n>] [--fresh] [--third-party hold|allow] [--storage <key>=<value>]… [--session-storage <key>=<value>]… [--no-storage]
```

- `<label>` — the proof's name: its captures are <label>-before and <label>-after (-motion, -states for those passes); default proof

| flag | what |
|---|---|
| `--ref <git ref>` | the commit the baseline is built from (capture --ref: a sibling worktree, reused for the same sha); default the profile's proof.ref (src/config/harness.ts), else develop |
| `--motion` | add the --motion pass |
| `--states` | add the --states pass |
| `--all` | all three passes: static, --motion and --states |
| `--build` | run the site's `pnpm build` before the first after capture |
| `--scheme light|dark` | prefers-color-scheme for every capture; default a pass in each of the profile's schemes (src/config/harness.ts; with two, the dark one's captures end in -dark), else light (one of `light`, `dark`) |
| `--widths w,w` | the static pass's viewport widths (capture --widths); default the profile's widths, else the built-in eight; --motion and --states keep their own |
| `--pages /a,/b` | only these routes, on every capture and compare; default the profile's proof.pages (src/config/harness.ts) unless --sample or --all-pages is given, else every page |
| `--sample <n>` | the static pass photographs the first n pages of each template (capture --sample); default the profile's proof.sample (src/config/harness.ts) unless --pages or --all-pages is given |
| `--all-pages` | every page of the build, whatever the profile's proof.pages or proof.sample: for a change that reaches every template, such as a kit upgrade |
| `--jobs <n>` | browsers at once, for every capture (capture --jobs) |
| `--fresh` | take every shot again, reusing none (capture --fresh) |
| `--third-party hold|allow` | other origins' scripts and connections on every capture (capture --third-party) (one of `hold`, `allow`) |
| `--storage <key>=<value>` | a localStorage key on both sides of every pass (capture --storage); the site's src/config/harness.ts is read by both without it (repeatable) |
| `--session-storage <key>=<value>` | the same for sessionStorage (capture --session-storage) (repeatable) |
| `--no-storage` | leave out the site's seed on both sides (capture --no-storage) |
| `--json` | print the proof as JSON: each pass's captures and compare report |

Exit: `0` every pass identical within the thresholds; `1` a line that is not ok in any pass — a difference, or a FLAKY or UNSTABLE shot that proves nothing either way — or a capture that failed (a page stalled twice, the build failed); `2` usage, no build, no browser, a seed that does not read, captures of two schemes, or a retake of another build (the tree rebuilt during the proof).

`--json` prints `{ label, ref, schemes, passes: [{ pass, scheme, before, after, retakes: { before, after } | undefined, report, seconds }], exit, failed?, evicted }`.

```bash
agentic-cms visual-parity proof
agentic-cms visual-parity proof nav-fix --states --build
agentic-cms visual-parity proof --all --ref main --json
agentic-cms visual-parity proof upgrade --all --all-pages --build   # a kit upgrade: every pass, every page
```

#### `visual-parity clean`

Removes old captures from .parity/visual/ — all but the newest, and every compare of a removed capture — and, with --cache, the shot cache; a capture still running is kept.

```bash
agentic-cms visual-parity clean [--keep 10] [--all] [--cache] [--dry-run]
```

| flag | what |
|---|---|
| `--keep <n>` | how many finished captures stay, the newest by the time they finished (default `10`) |
| `--all` | remove every finished capture (one still running, with no capture.json and under a day old, stays) |
| `--cache` | also empty .parity/shot-cache/, so the next capture takes every shot again |
| `--dry-run` | list what would go and what stays; remove nothing |
| `--json` | print the result as JSON |

Exit: `0` cleaned, or listed with --dry-run; `2` usage.

`--json` prints `{ removed: [label], kept: [label], bytes, cache, dryRun }`.

```bash
agentic-cms visual-parity clean --dry-run
agentic-cms visual-parity clean --keep 4 --cache
```

## look & measure

Layer: [design tools](parts.md#design-tools). `shot` · `probe` · `sheet`

### `shot`

One screenshot of a page or of an element on it, prepared like the harness prepares a page, with its box as JSON.

```bash
agentic-cms shot <route|url> [--url <base>] [--width 1440] [--height 900] [--scale 1] [--select <css> | --heading <regex>] [--transparent] [--trim] [--resize <w>] [--out <file>] [--storage <key>=<value>]… [--session-storage <key>=<value>]… [--no-storage] [--json]
```

- `<target>` — a route of the build (/about) or a URL

| flag | what |
|---|---|
| `--url <base>` | a served site (a dev server) instead of the build under .next |
| `--width <n>` | viewport width in px (default `1440`) |
| `--height <n>` | viewport height in px (default `900`) |
| `--scheme light|dark` | prefers-color-scheme; default the first of the profile's schemes (src/config/harness.ts), else light (one of `light`, `dark`) |
| `--motion` | play the animations (reveals at their start state, sequences running) instead of freezing them at the end state |
| `--wait <n>` | extra milliseconds to wait before measuring or photographing (default `0`) |
| `--scroll <y|into-view>` | scroll the page to y px, or the target into view (the default with a target under --motion) |
| `--select <css>` | the element: a CSS selector (the first match, or --index); with --heading, searched inside that section |
| `--heading <regex>` | the element: the section (article, [data-section]) holding the heading that matches — or, with --select, the section the selector is searched in |
| `--index <n>` | which match of --select or --heading, from 0 (default `0`) |
| `--scale <n>` | device scale factor (2 for a crisp crop) (default `1`) |
| `--pad <n>` | margin around the element's box, in px (default `24`) |
| `--transparent` | the element alone on a transparent ground: everything else hidden, the ancestors' backgrounds cleared |
| `--trim` | trim the transparent or same-colour edges (sharp) |
| `--resize <n>` | scale the result to this width in px (0: as photographed) (default `0`) |
| `--out <file>` | .png or .webp; default .parity/shots/<route>@<width>[--<target>].png |
| `--storage <key>=<value>` | a localStorage key on the page's origin, written before any of the page's scripts runs, over the site's src/config/harness.ts key by key; {now} in the value is the run's ISO time, {now:ms} its epoch milliseconds (repeatable) |
| `--session-storage <key>=<value>` | the same for sessionStorage (repeatable) |
| `--no-storage` | leave out the site's seed (the storage areas of src/config/harness.ts; its profile still applies): only the --storage and --session-storage given are seeded (a first visit) |
| `--json` | print one JSON document on stdout (progress goes to stderr) |

Exit: `0` written; `1` the target was not found on the page; `2` usage, no build, no browser, or a seed that does not read.

`--json` prints `{ url, route, width, height, scale, scheme, motion, seed: { storage, sessionStorage, at } | null, scrollY, target: { by, value, index, tag, id, box, pageBox } | null, out, image: { width, height, transparent, trimmed, resized }, console }`.

```bash
agentic-cms shot / --width 390 --scheme dark
agentic-cms shot / --width 390 --no-storage      # a first visit: what the site shows before a choice is stored
agentic-cms shot / --heading "fits the stack" --select ".card" --scale 2 --json
agentic-cms shot /about --url http://localhost:8000 --select "picture" --transparent --trim --out .parity/shots/loop.png
```

Removes the route (without a name, every route demo new wrote — a site's own *-demo folder is kept and named), every file the round created that nothing outside it imports — the candidates and whatever they alone use, found from the route's imports through new files only (the manifest demo new wrote, and git since the round began) — with their module.css, the round's assets (public/images/<name>-demo/) and next dev's generated route types while they still name the route (the production build's type check reads them); the component the candidates were copied from is never removed, and a new file something else imports (a piece the promoted section now uses) is kept and named.

```bash
agentic-cms demo clean [name] [--dry-run] [--json]
```

- `<name>` — the demo's name; without one, every route demo new wrote (a site's own *-demo folder only by its name)

| flag | what |
|---|---|
| `--dry-run` | print what would change; write nothing |
| `--json` | print { removed, kept } (and dryRun: true) |

Exit: `0` removed, or nothing to remove.

`--json` prints `{ removed, kept, dryRun? }`.

```bash
agentic-cms demo clean services
agentic-cms demo clean services --dry-run      # what would go, and what stays and why
agentic-cms demo clean                     # every *-demo route
```

## site

Layer: [the site's commands](parts.md#the-sites-commands). `init` · `setup` · `urls` · `serve`

### `init`

A site from the package: the wireframe example's code with a starter of the site's name in place of the example's content (a home page and the blog index whose copy is marked as placeholder, empty collections, neutral pictures), the agent files (rules and design skills), the config, a CI workflow and a manifest; or a refresh of an existing site's agent files.

```bash
agentic-cms init [dir] --name <Site> [--url <origin>] [--email <address>] [--force] [--light-only] | agentic-cms init [dir] --agent-files [--check | --diff <file> | --accept <file>] [--force]
```

- `<dir>` — where the site goes (default: the current directory)

| flag | what |
|---|---|
| `--agent-files` | only the rules (.claude/rules/), the design skills (.claude/skills/, .agents/skills/), AGENTS.md's scoped-rules table, written from the rules' frontmatter so Codex finds them (the one block of AGENTS.md the kit rewrites), and .claude/settings.json when it is missing (a site's own is never rewritten); a file the site edited is kept ("kept, kit changed" when the kit's text changed since the site took it), and a rule for a tool the site has not adopted — the components rule without src/config/components.json, the guard's config — is neither written nor checked |
| `--check` | with --agent-files: report each file — ok; modified (the site edited the kit's current text: passes); modified, required gone (the site's edit dropped a block the kit marks required, a list item or a paragraph ending in <!-- required -->, re-wrapped or unmarked still counting as kept — or .claude/settings.json no longer names the kit's marketplace or enables the editorial plugin: each named, with the kit's file it is in); modified, kit changed (the site edited it and the kit's text changed since its base: --diff, merge, --accept); stale (the kit has a newer one, or a rule's scope changed since the table); missing; unreadable (.claude/settings.json is not JSON) — and AGENTS.md too big past the 32 KiB Codex reads; a file the manifest records no base for is measured against the kit's text at the version the site was on (the manifest's version, else the last other one its package.json named in git), which the package keeps for every release, and noted ("no base: kit unchanged since 0.7.6"); exit 1 on any but ok and modified; write nothing |
| `--diff <file>` | with --agent-files: print the kit's change to a file since its base — the kit's text the site last took — as a unified diff (`git apply` reads it), the base from .agentic-cms/base/, the kit's releases or the site's git history; for a file with no base, from the kit's text at the version the site was on, or, when no release is known as its source, the site's whole file against the kit's text, which says so and is never applied whole; repeat for more files; write nothing (repeatable) |
| `--accept <file>` | with --agent-files: record the kit's current text as the base of a file the site merged by hand (its copy in .agentic-cms/base/ while the site's text differs, or while no release of the kit holds it), so --check calls it modified, the site's edit of the kit's current text, until the kit changes it again; repeat for more files; nothing else is written (repeatable) |
| `--name <Site>` | the site's name as it is spelled, required for a new site (a folder without content/; never taken from the folder's name): src/config/site.ts's name and short name, the starter's copy, content/VOICE.md's brand and the logo placeholder (public/images/brand/<slug>-logo.svg, its text and title); a site that has content/ takes none |
| `--url <origin>` | the site's origin, https://<host> without a path: site.ts's url, the canonicals, the sitemap and the feed; default https://<slug>.example, a stand-in on a reserved domain that the content lint marks as placeholder |
| `--email <address>` | the site's public address: site.ts's email and the home page's contact card; default hello@<slug>.example, a stand-in the lint marks |
| `--force` | overwrite files that exist, but never a site's own: its content/ and public/, src/config/site.ts and src/config/forms.ts (package.json and pnpm-workspace.yaml are always merged, never overwritten) |
| `--light-only` | a site without dark mode: the profile's schemes are ["light"], the example's colours single values with color-scheme: light, no theme script and no theme toggle, and STANDARD.md and the component catalogue without their dark-mode lines |
| `--json` | print the result as JSON |

Exit: `0` written, every agent file the kit's text or the site's edit of it, or --diff found nothing to merge; `1` --check found drift, or --diff printed a change; `2` usage, a new site without --name or with an empty one, a --url that is not an origin or an --email that is not an address (nothing is written), --name, --url or --email with --agent-files, a --diff or --accept name that is not one of the site's agent files (or, for --accept, is missing), a base --diff finds in neither its copy, the kit's releases nor the git history, or a --light-only edit that did not find its place in the example (nothing is written; a kit bug to report).

`--json` prints `{ target, version, created, updated, kept, lightOnly, site: { name, url, email, starter: true } | { starter: false } } | { version, files: [{ file, status, note?, bytes? }] } | --diff: { version, files: [{ file, status, base, from, diff, note? }] }`.

```bash
agentic-cms init my-site --name "My Site"
agentic-cms init . --name "My Site" --url https://my-site.com --email hello@my-site.com
agentic-cms init my-site --name "My Site" --light-only      # a site with one scheme, light
agentic-cms init . --agent-files          # after a kit upgrade: the new rules and skills
agentic-cms init . --agent-files --check  # what drifted, for CI
agentic-cms init . --agent-files --diff .claude/rules/styling.md    # the kit's change since the site took it
agentic-cms init . --agent-files --accept .claude/rules/styling.md  # merged by hand: the kit's text is its base
```

### `setup`

A clone made ready to work on, the steps after scripts/setup.sh got Node checked, pnpm and the dependencies: the browsers the kit drives (Chromium, WebKit), .env.local with this machine's addresses in ALLOWED_DEV_ORIGINS, the lint and the tests, then the URLs; each step keeps what is there, so a re-run takes seconds.

```bash
agentic-cms setup [--check] [--build] [--no-browsers] [--engines chromium,webkit] [--deps] [--no-public] [--port <n>] [--lab-port <n>] [--json]
```

| flag | what |
|---|---|
| `--check` | report each step — Node, pnpm, the browsers, WebKit's libraries, .env.local, the origins, the servers on the ports — and write, install and run nothing; exit 1 on a gap |
| `--build` | verify with pnpm build too (the content lint, the prerender, the SEO audit; about a minute), the starter's placeholders warnings (AGENTIC_CMS_PLACEHOLDERS=warn: this build deploys nothing) |
| `--no-browsers` | skip the browsers (a machine that only edits content; shot, probe, sheet, visual-parity and lab render need Chromium) |
| `--engines <a,b>` | the browsers to install: chromium (every kit command), webkit (the Safari-engine checks of docs/browsers.md) (default `chromium,webkit`) |
| `--deps` | on Linux, install WebKit's system libraries when WebKit does not launch: sudo, which asks for a password (without it, the line to run is printed) |
| `--no-public` | do not look up the public address (offline, or a machine no viewer reaches from outside) |
| `--port <n>` | the dev server's port (default: the -p of package.json's scripts.dev) |
| `--lab-port <n>` | the lab server's port (lab serve's) (default `8001`) |
| `--json` | print the report as JSON (the steps' progress and the commands' output go to stderr) |

Exit: `0` ready (a step left for the owner, sudo for WebKit's libraries, is printed, not failed); `1` a verify step failed, or --check found a gap; `2` the environment — Node older than 22.18, no package.json here, no pnpm or playwright-core, a browser install that failed — or usage.

`--json` prints `{ ready, check, steps: [{ step, status: ok|done|skipped|gap|todo|failed, detail, command? }], todo: [command], urls: <urls --json> | null }`.

```bash
agentic-cms setup                          # what bash scripts/setup.sh runs last
agentic-cms setup --check                  # what is missing; writes nothing
agentic-cms setup --deps                   # with WebKit's Linux libraries (asks for sudo)
agentic-cms setup --no-browsers --build    # a machine that only edits content, through the full gate
```

### `urls`

This machine's URLs for the dev server and the lab — localhost, the LAN, the public address — whether each server answers (the dev server said running only when it is this clone's own next dev, by its .next/dev/lock as serve reads it; another checkout's server on the port is named as such), and whether ALLOWED_DEV_ORIGINS in .env.local covers every address, without which a page opened there never hydrates; --write adds the missing ones.

```bash
agentic-cms urls [--write] [--no-public] [--port <n>] [--lab-port <n>] [--json]
```

| flag | what |
|---|---|
| `--write` | add the missing addresses to ALLOWED_DEV_ORIGINS in .env.local (made from .env.example when absent), as hostnames, keeping the file's other lines; then restart this clone's dev server |
| `--no-public` | do not look up the public address (api.ipify.org, then ifconfig.me; 4 s each) |
| `--port <n>` | the dev server's port (default: the -p of package.json's scripts.dev, else next dev's 3000) |
| `--lab-port <n>` | the lab server's port (lab serve's) (default `8001`) |
| `--json` | print the report as JSON |

Exit: `0` every address is in ALLOWED_DEV_ORIGINS (or was written); `1` an address is missing from it, or .env.local is, and --write was not given; `2` no dev port (no package.json's scripts.dev to read it from, and no --port), or usage.

`--json` prints `{ addresses: { lan, public, publicLookedUp }, dev: { port, up, own, ownPort, urls: [{ where, url }] }, lab: { port, up, urls }, origins: { file, exists, listed, missing, written } }`.

```bash
agentic-cms urls                           # the URLs to hand over, and a missing origin named
agentic-cms urls --write                   # the missing origins into .env.local
agentic-cms urls --no-public --json
```

### `serve`

The dev server and the lab for the owner's devices, started or found running, and every URL to hand over once each route answers: the origins checked first, next dev on the site's port on every interface, the lab when .parity/lab has scenes, every *-demo route and the root waited for, then one table — localhost, LAN and public × the routes, the lab's index and each /scene/<name> — until Ctrl-C stops both.

```bash
agentic-cms serve [--port <n>] [--lab] [--lab-port <n>] [--write-origins] [--fix-cache] [--no-public] [--timeout <s>] [--json]
```

| flag | what |
|---|---|
| `--port <n>` | the dev server's port (default: the -p of package.json's scripts.dev, else next dev's 3000); this site's next dev already running there, or on the port its lock (.next/dev/lock) names, is reused and left running, and anything else on the port is refused |
| `--lab` | start the lab server even when .parity/lab has no scene (it starts by itself when it has one) |
| `--lab-port <n>` | the lab server's port (lab serve's); when it is taken, serve goes on without the lab and says so (default `8001`) |
| `--write-origins` | add the addresses ALLOWED_DEV_ORIGINS lacks to .env.local before next dev starts, so they apply (urls --write's edit) |
| `--fix-cache` | when the dev log shows Turbopack's stale cache (Can't resolve '@vercel/turbopack-next/internal/…', after a production build), stop the server serve started, clear .next/dev and .next/cache/turbopack and start it again, once |
| `--no-public` | do not look up the public address (offline, or a machine no viewer reaches from outside) |
| `--timeout <s>` | how long next dev may take to be ready, and each route to answer, in seconds (default `120`) |
| `--json` | print each table as one JSON document per line instead (the progress goes to stderr) |

Exit: `0` stopped with Ctrl-C; `1` next dev exited on its own, or was not ready within --timeout (its log's tail is printed); `2` no dev port, the port held by something that is not this site's next dev, next not installed, or usage.

`--json` prints `{ dev: { port, pid, started, reused }, lab: { port, started, taken, urls, scenes: [{ name, urls }] } | null, hosts: [{ where, host }], routes: [{ path, ready, status, tail, urls: [{ where, url }] }], origins: { file, exists, listed, missing, written }, restarted }`.

```bash
agentic-cms serve                          # then hand over the URLs it printed; Ctrl-C stops it
agentic-cms serve --write-origins          # a new address of this machine, added before next dev starts
agentic-cms serve --fix-cache              # after a production build broke the dev server's compile
agentic-cms serve --lab --no-public --port 8002
```

## default gates

Layer: [the site's commands](parts.md#the-sites-commands). `seo` · `guard-email` · `check-components` · `check-site` — `seo`, `guard-email` read the site's registry and run in its root

What every change passes: `pnpm lint` runs ESLint, then `check-site` (the `check-components` pass first); `pnpm build` runs `pnpm lint`, `lint --production` and `docs --check` (content, above), `next build`, then `seo`, and `guard-email` last on a site whose `src/config/site.ts` turns `guardEmail` on (what `init` writes for a new site); CI runs them on every pull request.

### `seo`

The audit of every prerendered page after next build: title, description, canonical, Open Graph, headings, images, JSON-LD, robots, sitemap, internal links.

```bash
agentic-cms seo [--strict] [--report] [--json]
```

| flag | what |
|---|---|
| `--strict` | every WARN counts as a FAIL |
| `--report` | also write the findings to .parity/seo-report.txt |
| `--json` | print the findings as one JSON document |

Exit: `0` no FAIL; `1` a FAIL; `2` no build under .next/server/app.

`--json` prints `{ pages, findings: [{ level, route, rule, problem }], summary: { fails, warns, strict } }`.

```bash
agentic-cms seo                           # after next build
agentic-cms seo --strict --json
```

### `guard-email`

Fails when a served file of the build (a page, an RSC payload, the feed, a bundle) carries the site's e-mail address as text, naming each file and the fix; the build's last step on a site whose src/config/site.ts turns guardEmail on, a step a site without the key may add.

```bash
agentic-cms guard-email [--domain <host>]… [--json]
```

| flag | what |
|---|---|
| `--domain <host>` | a domain whose addresses must not appear; default: the host of site.url from src/kit.ts (repeatable) |
| `--json` | print { domains, scanned, hits: [{ file, addresses }] } |

Exit: `0` no address as text; `1` an address in a served file (each named); `2` usage, or no build under .next.

`--json` prints `{ domains, scanned, hits: [{ file, addresses }] }`.

```bash
agentic-cms guard-email
agentic-cms guard-email --domain acme.example --json
```

### `check-components`

The component library's placement guard, the first pass of check-site (which pnpm lint runs after ESLint), alone: the layers there and every file under src/components in one, every component the library exports in its catalogue, every section file in the registry, route files only in src/app's known route folders, no component elsewhere, CSS modules and @keyframes only where the library keeps them, every owner and every allow entry with its reason; and the engines held: the required agentic-cms/* rules as ESLint resolves them for a sample file per layer, set as componentRules() makes them of the config, and every inline disable of one with its reason, listed; what the preferred tier guides warns and fails nothing — a transition declared in CSS outside the motion layer, an inline disable of another rule with no reason, a preferred rule set otherwise than the config makes it; the config is src/config/components.json.

```bash
agentic-cms check-components [--json]
```

| flag | what |
|---|---|
| `--json` | print the report as one JSON document |

Exit: `0` every file where the library keeps it (a file on the config's inherited list, and a running design round's candidates, pass), and the engines' rules held; warnings, if any, printed; `1` a finding (each with its file, the check, and the fix); `2` no src/config/components.json here, a config that does not read (an unknown key named with the nearest one), or usage.

`--json` prints `{ config, layers: { motion, ui, patterns, sections, sectionFolders }, inherited, candidates, disables: [{ file, line, rules, reason }], allowed: [{ rule, files, reason }], findings: [{ check: layers|catalogue|registry|routes|components|styles|keyframes|inherited|owners|allow|disables|preset, file, problem, fix }], warnings: [{ check: transitions|disables|preset, file, problem, fix }] }`.

```bash
agentic-cms check-components             # the components pass alone, without the site's
agentic-cms check-components --json | jq '.findings[] | .file'
```

### `check-site`

The site check, which pnpm lint runs after ESLint: every pass of check-components, then the site's own — a *-demo route only demo new's (its demo.json) or the lab's, a round's pictures only while its route is there; every exception added since the merge base listed with its reason (a route exception, an owner, an allow entry, an ignores glob, an inline disable), the frozen inherited list and the baseline only shrinking; package.json's lint (ESLint, then check-site) and build (pnpm lint, lint --production, docs --check, next build, seo, and guard-email when src/config/site.ts turns guardEmail on) holding the gates, a guardEmail turned off saying why ({ off: <why> }, listed with the exceptions once added); a workflow on pull requests running the lint, the tests, the build and the agent-file check; what is left of the kit's example (its brand by line, its posts, catalogue pages, pictures and collection entries by path, by bytes and by entry); and, as warnings that fail nothing, a script of the site's own under scripts/ that drives Playwright, runs sharp over public/ or starts next dev, and a machine's address in next.config.*, each naming the kit's command and quiet with an allow entry of agentic-cms/site-tools and its reason. A site that took 0.8.2 with engine bypasses and leftovers keeps them in the baseline, which --baseline writes and every later run holds.

```bash
agentic-cms check-site [--baseline] [--base <ref>] [--json]
```

| flag | what |
|---|---|
| `--baseline` | write what the site holds now of the rules a baseline holds — the engines' findings (agentic-cms/copy, head, forms, tags, email) as its ESLint reads them, a round made by hand (rounds) and the example's leftovers (example-brand, example-content) — into src/config/components.json's baseline, one entry per file and rule with its count and an empty reason: the whole list when the config has none (the pull request that takes 0.8.2), else the list shrunk to what is left, an entry gone or lowered; it never grows one, refusing an entry new or raised. The preferred tier's warnings and the findings of the gates and the config are never baselined (docs/migrating-to-0.8.2.md) |
| `--base <ref>` | the branch or commit the exceptions and the baseline are compared with, through its merge base with HEAD (default: the pull request's base branch in CI, GITHUB_BASE_REF, else origin/HEAD, origin/main or main; a checkout without that history — no git, no commit, a shallow clone — compares nothing and says so) |
| `--json` | print the report as one JSON document |

Exit: `0` every pass held (warnings, if any, printed); with --baseline, the list written or already current, and nothing left that no baseline takes; `1` a finding of any pass, the components pass's included (each with its file, the check, and the fix); with --baseline, growth refused or a finding no baseline takes left (the list is written, never grown, either way); `2` no src/config/components.json here, a config that does not read, a --base that names no commit or a checkout without the history it needs, or usage.

`--json` prints `{ config, kit, components: { layers, inherited, candidates, disables, allowed }, rounds, base: { ref, commit } | null, history, added: [{ kind, name, reason, rules? }], baseline: { entries, held }, findings: [{ check: <check-components' checks>|rounds|exceptions|scripts|ci|tools|leftovers|baseline, rule?, file, problem, fix }], warnings: [{ check: transitions|disables|preset|tools|baseline, file, problem, fix }] }; with --baseline, { config, written, first, baseline: [{ file, rule, count, reason }], found: [{ file, rule, count, findings: [{ at, problem }] }], shrunk, removed, refused: [{ file, rule, count, reason, found }], remaining, warnings }`.

```bash
agentic-cms check-site                   # what pnpm lint runs after eslint
agentic-cms check-site --base origin/develop  # the exceptions this branch adds to develop
agentic-cms check-site --baseline          # taking 0.8.2: the bypasses and leftovers into the baseline; later, the list shrunk
agentic-cms check-site --json | jq '.added'
```

## opt-in steps

Layer: [the site's commands](parts.md#the-sites-commands). `critical-css` · `assemble`

What a site adds to its build when it needs them: `critical-css` for the first paint, `assemble` last for a Node host.

### `critical-css`

Inlines each prerendered page's critical CSS (the rules its own HTML uses, its stylesheets' @font-face) and loads the stylesheets without blocking the first paint; the build's pages and the standalone package's copy.

```bash
agentic-cms critical-css [--check] [--json]
```

| flag | what |
|---|---|
| `--check` | change nothing: only fail when a page still waits for a stylesheet before it paints |
| `--json` | print the report as one JSON document |

Exit: `0` every page paints without waiting for a stylesheet; `1` a page still links a stylesheet that blocks its paint (each named); `2` usage, or no prerendered pages under .next/server/app.

`--json` prints `{ dirs, pages, inlined, skipped, bytes: { inlined, before, after }, blocking: [{ page, sheets }] }`.

```bash
agentic-cms critical-css                  # after next build, before seo and assemble
agentic-cms critical-css --check --json
```

### `assemble`

Packages a standalone build for a Node host: public/ and .next/static copied into .next/standalone — into its folders, never as them — then every file of both checked there; nothing is packaged while the starter's placeholder copy or address remains.

```bash
agentic-cms assemble [--check] [--json]
```

| flag | what |
|---|---|
| `--check` | copy nothing: only check the package against public/ and .next/static (in CI, or after a copy made by hand) |
| `--json` | print the report as one JSON document |

Exit: `0` the package holds every file of public/ and .next/static; `1` a placeholder left from the starter under content/ or src/config/ (each named by line; nothing packaged unless AGENTIC_CMS_PLACEHOLDERS=warn, for a CI run that deploys nothing), a file missing or different, or a copy nested inside the folder it should fill (each named); `2` usage, or no standalone build (output: "standalone", then next build).

`--json` prints `{ package, copied, removed, parts: [{ from, files, bytes }], missing, differ, nested, extra }`.

```bash
agentic-cms assemble                      # after next build: the last step of a standalone site's build
agentic-cms assemble --check --json
```
