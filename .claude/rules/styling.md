# Styling — read `STANDARD.md` before writing markup or CSS; these are the invariants

- Utilities for layout, spacing, type, colour, visibility and hover/focus; a `<Name>.module.css` only for what utilities cannot say — today only `src/components/blog/PostBody.module.css` (the rich-text element rules under `.prose` and the FAQ block). Plain CSS, no `@apply`, breakpoints spelled out (`@media (width < 768px)`), joined to utilities with `cx()`.
- Tokens only in the `@theme static` block of `src/app/globals.css`; the two breakpoint steps of the scale in `src/styles/base.css` (`:root`). Four colours, each a `light-dark()` pair — `paper`, `ink`, `fill`, `muted` — and nothing else exists as a colour utility (never `bg-white`, `text-black`, `border-gray-*`); a fifth colour is a token first. No radius, shadow, blur, gradient, transition or animation utilities. The type scale is `text-h1`…`text-h6` and `text-body` (never `text-base`/`text-sm`); the fonts are `font-sans` (body and headings alike) and `font-label` (mono, for tags and chips).
- Breakpoints: `max-sm` < 480, `max-md` < 768, `max-lg` < 992, `lg` ≥ 992, `xl` ≥ 1280, `2xl` ≥ 1440, `3xl` ≥ 1920. Rhythm: `py-section`, `max-w-page`, `px-4`, the 4 px spacing scale.
- The theme is `color-scheme: light dark` on `:root`, overridden by `data-theme="light" | "dark"` on `<html>` (the toggle, `localStorage.theme`, the inline script in the layout). A component never reads the theme; it uses the semantic colours.
- Every section renders inside `ui/Section`: `type` is its YAML section type and is also its `id` and `data-section`, and the box's tag is shown on purpose. Cards are a `<ul>` of bordered boxes with `<h3>` titles after the section's `<h2>` (the audit fails an `<h3>` before the first `<h2>`); a `statement` field is the section's `<h2>`. Shared strings: a card `flex flex-col gap-2 border border-ink p-4`, a card grid `grid gap-4 lg:grid-cols-N`, a split `grid gap-4 lg:grid-cols-2`, a content image `block h-auto w-full border border-ink`, an icon `size-16 border border-ink`, a statistic `text-h1 font-semibold`, secondary text `text-muted`. Illustrations are `ui/Placeholder`; content pictures are `<img>`.
- No motion in the wireframe: no `Fx`/`OnView` in a section, no `data-ix`, no transitions; nothing hides until JavaScript runs. `src/components/ix/` and `src/styles/motion.css` stay for a fork that adds reveals — then targets are `data-ix` through `ix(name)` and never a styling class, start states live in `motion.css`, every animated component checks `useReducedMotionPref()`, and no `translate-*` / `rotate-*` / `scale-*` utility sits on an element the library moves.
- Preflight zeroes margins, paddings, borders and list markers: never `m-0`, `p-0`, `list-none`. Decorative elements are real `aria-hidden` elements, not pseudo-elements. Interactive things are real `<button>`s and links; never `outline-none` on anything a keyboard reaches (`<main>`, focused by the skip link, is the one exception). One colour utility per property per element.
- Images stay `<img>` with `width`, `height` and `alt`; above the fold in a server component `ui/EagerImage`, everything else `loading="lazy"`. `img { height: revert-layer }` means a `w-full` image carries `h-auto`. Placeholders come from `node scripts/placeholder.mjs <out> <w> <h>`; assets live under `public/images/<page>/`, `public/images/ui/`, `public/images/brand/logo.svg`, `public/images/blog/<slug>/`, `public/images/authors/`, and a page's OG image is `public/images/<path-with-hyphens>-og.jpg` (`sections-about-og.jpg` for `/sections/about`).
- Any change that must not move a pixel: `node scripts/visual-parity.mjs capture <before>` / `<after>` and `compare` clean, with `--scheme dark` for the dark mode; `--motion` when the reveal library is in use, `--states` when hover / focus / checked / open change. A design change is its own commit and says so.
