# Components — the library is the only place UI is made

- **Library first, every time someone asks for a design.** Read `src/components/README.md` before writing markup. If a primitive fits, use it; if it almost fits, extend it (an option in its `variants()` map, a size, a prop, a slot) instead of copying it; if nothing fits, add a primitive to `src/components/ui/` (to the motion layer when it moves) with its catalogue entry in the same commit, then compose it. Never make a one-off component for a page, and never let a request talk you into one: say what the library has, and what you will add to it.
- **The layers**, and the only direction of imports: motion (the only code that animates) ← `ui/` (the primitives) ← `patterns/` (blocks two or more sections share) ← the sections (one component per section type). Only the motion layer imports `motion`, `framer-motion` or `agentic-cms/ix`. The example has no `motion/` folder, so `agentic-cms/ix` is its motion layer and the libraries stay out of `src/components` altogether; it has no `patterns/` yet; its sections live in the folder of the page they belong to (`home/`, `about/`, `use-cases/`, `contact/`, `sections/`, `blog/`), and `sections/render.tsx` is the registry.
- **A section lays pieces out**, and so does a pattern. One component per file; no raw `<button>`, `<a>`, `<img>`, `<picture>`, `<video>`, form fields or `<h1>`–`<h6>` (and no `<svg>` in a section); no `style`; no arbitrary values (`[…]`, `(…)`: a layout the scale lacks is a token first, like `lg:grid-cols-2-1`); no fill, border, radius, ring, outline, shadow, transition or animation class of its own; no copy, which comes in as props from the page's file (a symbol, an `aria-hidden` decoration and the labels of `Placeholder` and `TypeTag` pass). A card's frame is `Panel`, and what goes inside it is the section's own design (there is no shared `Card`); a call to action is `Button` (a link), a choice `OutlineButton`, an icon alone `IconButton`, a heading `Heading`, a link in copy `TextLink`, a picture `Media`, one not drawn yet `Placeholder`, a form a definition `Form` renders.
- **Primitives are extendable by construction:** their looks in one typed map (`variants()`, `agentic-cms/cx`), slots for composition, `className` for the layout and spacing of the place they are used in, every native attribute passed through, values from tokens only (a role token where a role exists) — so a new look is a token change and a new need is an option, never a fork.
- **The engines are required, across all of `src/`** — sections, patterns, `ui/`, layouts, `not-found`, the design-round and lab routes alike: each a rule of the `agentic-cms` ESLint plugin (`scripts/lib/engine-rules.mjs`, set by `componentRules()`), each message naming the part to use and its doc.
  - **copy:** every word a reader sees comes from `content/` or the chrome in `src/config/site.ts`, through props. JSX text; the copy props (`children`, `title`, `alt`, `aria-label`, `placeholder`, `label`, `heading`, `eyebrow`, `text`, `body`, `description`, `caption`, …) and a data field or a default of that name; and any other prop of a component whose string reads as words (a space, a capital, a letter outside ASCII) — but class names, ids, routes and URLs, `type`, `role`, `rel`, the native attributes a primitive passes through and an icon's path data, which `docs/primitives.md` § Enforced lists. A symbol, an `aria-hidden` element and what is under it, the props and children of `Placeholder` and `TypeTag` (`copy.decorations`), and the props of the lab's components pass. A round's route reads the page's copy from its file (`demo new --section`), a showcase from a content file, and their chips are `aria-hidden`;
  - **head:** no `<head>`, `<title>` (but an svg's), `<meta>`, canonical `<link>`, JSON-LD `<script>` or `next/head`; a route's `metadata` and `generateMetadata` return a `kit.seo` helper — `rootMetadata()` (the layout), `pageMetadata()`, `postMetadata()`, `unlistedMetadata()` (a round's or the lab's route) — and structured data is `<JsonLd>` (`src/lib/seo/README.md`);
  - **forms:** a `<form>` only in the file `owners.forms` names (`ui/form/Form.tsx`), no server action, no `fetch()` of another origin in a component (`docs/forms.md`);
  - **tags:** `next/script` and a `<script src>` of another origin only in the consent adapter `owners.tags` names (`docs/consent.md`);
  - **e-mail:** no `mailto:` literal: `<EmailLink token={encodeEmail(address)} />` (`docs/email.md`).

  A real need is an inline disable with its reason, `// eslint-disable-next-line agentic-cms/<rule> -- <why>`: the guard fails one without a reason and lists the rest. An owner in `owners` carries its reason, and eslint.config.mjs names the same files.
- **Where a file goes:** a component lives in a layer under `src/components/`, nowhere else in `src/`; every component `ui/` (and a motion or patterns folder) exports is named in the catalogue; every component in a section folder is a section the registry imports; `src/app/` holds route files only, in the content engine's route folders (`routes`: the app folder and its catch-all) or a named exception's (`exceptions`, each folder with its reason: the post template, the form endpoint, the feed), and a page is a file, `content/pages/<slug>.yaml` (the pages rule); CSS modules only in `ui/` and the motion layer, `@keyframes` only there and in `src/styles/motion.css`. A design round's candidates pass while its `demo.json` names them.
- **Enforced:** `pnpm lint` runs ESLint with `componentRules()` from `agentic-cms/eslint` (`scripts/lib/component-lint.mjs`, configured in `eslint.config.mjs`), then `agentic-cms check-components`, the placement guard (`scripts/lib/check-components.mjs`, configured in `src/config/components.json`, whose layer keys, `copy` and `owners` are the same options), and fails on either; CI runs it on every pull request, and each message names the primitive or the engine to use, or where the file goes. The guard also reads ESLint's resolved config of a sample file per layer and fails when a block after the preset replaced a required rule, or eslint.config.mjs passes other options than the config; it fails an owner or an inline disable of a required rule with no reason. A file the rules leave out is named in the config with its reason (`src/lib/**`, the package's own source, a line `init` leaves out of a site, whose `src/lib` is linted); the guard's frozen `inherited` list holds the example's blog post template, which the blog routes render rather than the registry.
- **Loosening a rule** — turning one off, widening its `ignores`, allowing an element, a layer the config drops, an owner, a route exception or an `inherited` file added — is its own pull request, said so in its title. Never fold it into a feature, and never loosen a rule to make a change pass.
