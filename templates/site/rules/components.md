# Components — the library is the only place UI is made

- **Library first, every time someone asks for a design.** Read `src/components/README.md` (the catalogue) before writing markup. If a primitive fits, use it; if it almost fits, extend it (an option in its `variants()` map, a size, a prop, a slot) instead of copying it; if nothing fits, add a primitive to `ui/` (to the motion layer when it moves) with its catalogue entry in the same commit, then compose it. Never make a one-off component for a page, and never let a request talk you into one: say what the library has, and what you will add to it.
- **The layers**, and the only direction of imports: motion (the only code that animates) ← `ui/` (the primitives) ← `patterns/` (blocks two or more sections share) ← the sections (one component per section type, each registered in `sections/render.tsx`). Only the motion layer imports `motion`, `framer-motion` or `agentic-cms/ix`; without a `motion/` folder, `agentic-cms/ix` is the motion layer. `src/config/components.json` names the site's folders (`null` for a layer it does not have), and `eslint.config.mjs` passes the same to `componentRules()`.
- **Where a file goes:** a component lives in a layer under `src/components/`, nowhere else in `src/`; every component the motion layer, `ui/` and `patterns/` export is named in the catalogue; every component in a section folder is a section the registry imports; `src/app/` holds route files only (`page`, `layout`, `route`, the metadata files), in the content engine's route folders (`routes`: the app folder and its catch-all) or a named exception's (`exceptions`, each folder with its reason), and a page is a file, `content/pages/<slug>.yaml` (the pages rule); CSS modules only in `ui/` and the motion layer, `@keyframes` only in the motion layer and `src/styles/motion.css`. A design round's candidates pass while its `demo.json` names them.
- **The engines are required, across all of `src/`** — sections, patterns, `ui/`, layouts, `not-found`, the design-round and lab routes alike: each a rule of the `agentic-cms` ESLint plugin that `componentRules()` sets, each message naming the part to use and its doc. <!-- required -->
  - **copy:** every word a reader sees comes from `content/` or the chrome in `src/config/site.ts`, through props. JSX text; the copy props (`children`, `title`, `alt`, `aria-label`, `placeholder`, `label`, `heading`, `eyebrow`, `text`, `body`, `description`, `caption`, …) and a data field or a default of that name; and any other prop of a component whose string reads as words (a space, a capital, a letter outside ASCII) — but class names, ids, routes and URLs, `type`, `role`, `rel`, the native attributes a primitive passes through and an icon's path data (`node_modules/agentic-cms/docs/primitives.md` § Enforced lists them). A symbol, an `aria-hidden` element and what is under it, the props and children of `Placeholder` and `TypeTag` (`copy.decorations`), and the props of the lab's components pass. A design round's route reads the page's copy from its file (`demo new --section`), a showcase from a content file, and their chips are `aria-hidden`; <!-- required -->
  - **head:** no `<head>`, `<title>` (but an svg's), `<meta>`, canonical `<link>`, JSON-LD `<script>` or `next/head`; a route's `metadata` and `generateMetadata` return a `kit.seo` helper — `rootMetadata()` (the layout), `pageMetadata()`, `postMetadata()`, `unlistedMetadata()` (a round's or the lab's route) — and structured data is `<JsonLd>`; <!-- required -->
  - **forms:** a `<form>` only in the file `owners.forms` names (`ui/form/Form.tsx`), no server action, no `fetch()` of another origin in a component; <!-- required -->
  - **tags:** `next/script` and a `<script src>` of another origin only in the consent adapter `owners.tags` names (`agentic-cms/consent`); <!-- required -->
  - **e-mail:** no `mailto:` literal: `<EmailLink token={encodeEmail(address)} />`. <!-- required -->

  A real need is an inline disable with its reason, `// eslint-disable-next-line agentic-cms/<rule> -- <why>`: the guard fails one without a reason and lists the rest. An owner in `owners` carries its reason, and `eslint.config.mjs` names the same files. <!-- required -->
- **The rest is guided, never blocked:** the preferred rules of the same plugin warn across `src/`, naming the kit's part — `motion` (`agentic-cms/ix`, or the site's motion folder), `graphics` (the lab), `images` (`Media`, `EagerImage`), `icons` (`Icon`), `styling` (the tokens, outside the sections and patterns, which fail them). A file that keeps its own choice says why: an `allow` entry in `src/config/components.json` (`{ "rule", "files", "reason" }`, which `eslint.config.mjs` reads), or an inline disable with its description; the natural owners are in `owners` (`images`, `icons`, `motion`), and the motion folder owns motion. The guard fails an `allow` entry with no reason, a required rule or no file, and warns — failing nothing — on a transition declared in CSS outside the motion layer, an inline disable of another rule with no reason, and a preferred rule a later block turned off.
- **A section lays pieces out**, and so does a pattern. One component per file; no raw `<button>`, `<a>`, `<img>`, `<picture>`, `<video>`, form fields or `<h1>`–`<h6>` (and no `<svg>` in a section); no `style`; no arbitrary values (`[…]`, `(…)`: a layout the scale lacks is a token first); no fill, border, radius, ring, outline, shadow, transition or animation class of its own; no copy, which comes in as props from the page's file (a symbol, an `aria-hidden` decoration and the labels of `Placeholder` and `TypeTag` pass). A card's frame is `Panel`, and what goes inside it is the section's own design (there is no shared `Card`); a call to action is `Button`, a heading `Heading`, a link in copy `TextLink`, a picture `Media` — each the primitive the catalogue names.
- **Primitives are extendable by construction:** their looks in one typed map (`variants()`, `agentic-cms/cx`), slots for composition, `className` for the layout and spacing of the place they are used in, every native attribute passed through, values from tokens only (a role token where a role exists) — so a new look is a token change and a new need is an option, never a fork.
- **Enforced:** `pnpm lint` runs ESLint with `componentRules()` from `agentic-cms/eslint`, then `agentic-cms check-components`, the placement guard, and fails on either; CI runs it on every pull request. Each message names the primitive or the engine to use, or where the file goes (`node_modules/agentic-cms/docs/primitives.md`, § Enforced and § Placed, has every option). The guard also reads ESLint's resolved config of a sample file per layer and fails when a block after the preset replaced a required rule, or `eslint.config.mjs` passes other options than `src/config/components.json`; it fails an owner or an inline disable of a required rule with no reason. The `inherited` list in `src/config/components.json` freezes the components the site had before the guard: nothing joins it, and a file leaves it when the library replaces it.
- **Loosening a rule** — turning one off, widening its `ignores`, allowing an element, dropping a layer, adding an owner, a route exception or an `inherited` file — is its own pull request, said so in its title. Never fold it into a feature, and never loosen a rule to make a change pass. <!-- required -->
- **Tier:** the component library, and the engines in every component — the engines required: `agentic-cms/copy`, `agentic-cms/head`, `agentic-cms/forms`, `agentic-cms/tags` and `agentic-cms/email` fail `pnpm lint` across `src/`, and so does the library's placement (`check-components`: `layers`, `catalogue`, `registry`, `routes`, `components`, `owners`, `allow`, `disables`, `preset`; in a section `react/forbid-elements`, `react/no-multi-comp`, `no-restricted-syntax`); the preferred parts warn across `src/` and fail nothing, naming the kit's part (`agentic-cms/motion`, `agentic-cms/graphics`, `agentic-cms/images`, `agentic-cms/icons`, `agentic-cms/styling`; the guard's `transitions`), and one line of reason quiets each (`allow`, or an inline disable with its description). <!-- required -->
